# Model Integration Design

`framework/src/t01c-cli.ts` wires the T01-C graph. Coverage analysis and candidate provenance are provided by `framework/src/runtime/coverage-analysis.ts` and `adapters/expresscart/source-identity.ts`. Each coverage result includes category, exact tag comparison, conservative confidence and uncertainty. `framework/src/runtime/model-provider.ts` contains explicit Gemini Gherkin and Java providers, plus fake providers used only by tests. Model calls use `maxRetries: 0`; a timeout abort signal is passed to LangChain and is covered by an offline test. Human review remains a LangGraph pause/resume and an ACCEPT only authorizes implementation for the current candidate revision.

After current ACCEPT, `framework/src/runtime/java-artifact-registry.ts` registers the generated class immutably and binds it to candidate, revision, source and approval. Reset-token candidates must use the source-grounded `po.CustomerPasswordResetPage`; the isolated harness stages its adapter implementation and the existing `po.PageObject` base with the exact registered generated class. `adapters/expresscart/generated-test-harness.ts` and `adapters/expresscart/experiment.ts` stage/compile/run only those approved files. `framework/src/contracts.ts` computes technical eligibility from structured compile/fixture/E2E/cleanup and repeat references; research oracle, novelty, and acceptance remain separate.

Each CLI run uses `framework/src/runtime/model-call-ledger.ts` for durable append-only model-call reservation/result records and fail-closed limits (no retries); `framework/test/model-call-ledger.test.ts` covers restart and exhaustion. Live generation requires explicit authorization flags. Five explicitly authorized Gherkin invocations returned no output: four returned `API_KEY_INVALID`; one bounded attempt failed at fetch. Three over-budget prompt preflights were rejected locally with zero provider calls. The fifth attempt includes sanitized prompt/hash evidence and one reserved/result pair, but no successful live response exists. That authorization is exhausted and no candidate was produced. An offline synthetic Java pipeline compiled successfully with Maven; it is test evidence only, not research evidence.

Repair selection requires `ExecutionReference.failureClassification=GENERATED_TEST_DEFECT`; application behavior failures, environment/harness failures, and unclassified failures do not invoke repair. This fail-closed policy is covered by `framework/test/integration/workflow.test.ts`; it classifies evidence but does not independently determine the real-world root cause.

Filesystem-only traversal/symlink checks and the Docker-backed adapter lifecycle test pass outside the managed sandbox. The adapter lifecycle test verifies scoped fixture cleanup and refuses to execute an unregistered artifact. A Gemini-generated candidate E2E, successful live model telemetry, and the complete human-review-to-Selenium lifecycle remain unverified. Build/test results and blockers are in `TEST-RESULTS.md` and `VALIDATION-AND-REPAIR-RESULTS.md`. This progress does not advance a gate or reduce the 8-application / 40-case research scope.

## T01-C offline review correction

Production `RuntimeServices.repairJava` is wired in `framework/src/t01c-cli.ts`. It permits at most two repair attempts and only for compile/E2E records classified `GENERATED_TEST_DEFECT`. Responses are durably recorded before repair registration; a consumed reservation without recoverable output blocks replay. `framework/src/runtime/java-artifact-registry.ts` keeps the first generated Java immutable, creates separately hashed `REPAIRED` artifacts chained to the current and first artifacts, verifies the chain, and requires every original assertion call to remain. The registered repaired artifact is accepted by the same verifier used by `adapters/expresscart/generated-test-harness.ts`.

`framework/src/runtime/validation-invocation.ts` allocates a unique evidence directory per attempt. Stage outcomes retain invocation ID, artifact hash/origin and source pin. The adapter lifecycle integration exercises two attempts and verifies scoped cleanup after an E2E refusal; a failure-injection branch verifies cleanup failure is BLOCKED. Process restart/replay, generated compile failure, repair compilation, and artifact hash mismatch have offline test coverage. The process-termination crash-recovery E2E remains opt-in and skipped. The fake-provider repair record is `docs/tasks/T01-C/evidence/verification/rerun-20261108-offline-review-fixes-03/offline-repair-loop.json`; it explicitly marks fixture, Selenium, and cleanup NOT_RUN. No new Gemini call occurred, and the live model-backed Java/Selenium path remains unverified.
