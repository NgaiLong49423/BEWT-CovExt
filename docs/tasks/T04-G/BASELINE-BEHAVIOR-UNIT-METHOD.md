# Behavioral Baseline Unit Method

Scope: Bludit, Claroline, ExpressCart, Joomla, MantisBT, MediaWiki, and PrestaShop at pinned BEWT commit 0501249ff3e9a5ea83a06155cd2971dc36197056; Kanboard is excluded. The builder requires a Git checkout at this exact commit and checks its tree SHA. It enumerates Git tree blobs, reads source files from that checkout, computes each Git blob ID from the bytes, and compares feature/Java path and SHA with T04-D before extracting excerpts. A mismatch or missing source fails closed as NOT_VERIFIED.

Feature files, Scenario headers, Java suite entries, assertions, and behavioral units differ. Counts: 227 feature files, 204 explicit Scenario headers, 226 feature-to-Java mappings, one feature-only, 228 Java suite entries including two Java-only. The 227 mapped feature records contain 314 Java assertion calls; the two Java-only classes add two more, for 316 assertion-call lines total. These are not unique behavior counts. A unit is a distinct actor/precondition/action/observable/oracle; multiple cases may cover one. Split/merge only with semantic evidence. All records are provisional NEEDS_REVIEW; no denominator is established.

Taxonomy: Normal flow, Negative/validation, Boundary condition, Authorization/role, State/lifecycle, Search/navigation. Keyword labels use pinned Gherkin only; T04-D heuristic tags do not verify behavior. Login and administrator wording often describes a shared setup fixture and can create false-positive role/authentication labels; all labels remain provisional.

Quoted Gherkin labels, expected messages, normal test data, and Java assertion literals are preserved. Redaction targets values entered into password/token/secret fields and explicit secret-like assignments, replacing only the sensitive value while preserving quotes and syntax. No complete source files are copied into the catalog. Runtime image, configuration, fixture/reset, cleanup, and Selenium feasibility remain unverified. No official RQ2 denominator or gain is supported.
