# Kanboard encrypted raw-evidence primitive — offline prototype

- Branch `task/kanboard-ledger-hardening`, based on main `22d3813bd92cc6ec0c5b2d0d766b6ba3fcb72170`. This commit extends the prior caller-supplied write-once ledger; it does not run Maven, Docker, Cloud or Selenium.
- `storeEncryptedArtifact` accepts a caller-provided 32-byte key and raw bytes in memory, encrypts with Node AES-256-GCM and writes only an authenticated ciphertext envelope via temporary file plus exclusive hard link. Permitted names: Maven stdout, Maven stderr and original Surefire XML. A resolved evidence directory with any `.git` ancestor or a `bewt-original` path component is rejected; private artifact files are limited to 16 MiB. Paths, plaintext bytes and keys are not put in the JSON envelope. The envelope does expose run/artifact identity, length through ciphertext, and plaintext SHA-256; hashes may reveal equality or permit guessing of low-entropy content.
- AAD binds both run ID and artifact name. Each run uses process-local unique random 96-bit nonces, and an in-process guard prohibits changing keys within a run or reusing a key between runs. These guards do not span process restarts or multiple hosts. The operator must generate and securely preserve an independent cryptographically random key for every run, outside the repository; losing the key loses the raw evidence. Key lifecycle, permissions/ACLs, memory exposure, backup and cross-process uniqueness have NOT been independently validated.
- `decryptArtifact` returns plaintext only in caller memory; authentication, identity, encoding/size and hash mismatches fail closed. `verifyRawArtifactBinding` decrypts three private artifacts and compares their hashes with the caller-supplied summary. It always leaves `executionVerified: false` and `sanitizationLinkVerified: false`. Hash binding proves only consistency of supplied data; it does not prove a process actually ran or that sanitization was correct.
- Files are not protected from later deletion or modification; authentication detects tampering when checked. Hard-link publication does not provide fsync crash durability. Temporary files, in-process buffers/keys and metadata require a trusted, access-controlled host; Node mode bits do not establish Windows ACLs, and hostile filesystem races are outside this prototype. No production security or runtime readiness is claimed.
- Offline tests exercise plaintext/key nonpersistence in ciphertext, no-overwrite, wrong key, ciphertext/tag/hash tampering, AAD identity mutation, malformed base64, process-local nonce/key separation, non-regular files and refusal to write within Git/source trees. Final suite: 44 PASS, 0 FAIL, 0 skipped, exit 0; `evidence/encrypted-20261110-r3/offline-tests.txt`. Earlier r1/r2 tests are retained.

Before actual experimental use, obtain independent cryptographic/security review, define approved private storage and backup/retention, verify Windows/Cloud ACLs, key generation/delivery/recovery, cross-process key uniqueness, sanitized artifact provenance and integrity, and build a trusted execution/cleanup orchestrator. Cloud-only policy, exact VM identity, exclusive runtime lease, isolation and signed firewall gates remain mandatory. G0 remains `BLOCKED_EVIDENCE`.
